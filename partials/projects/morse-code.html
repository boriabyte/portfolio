Morse Code Player

ESP32-driven Morse code transceiver: text typed into the serial console is translated letter-by-letter into Morse timing and played back audibly through a piezo buzzer while the corresponding characters are shown on a 16×2 I2C LCD.

Stack

Arduino IDE and C++ (Arduino framework). Wire for the I2C bus, LiquidCrystal_I2C for the display, and Tone32 as a drop-in replacement for the tone()/noTone() functions missing on this ESP32 core.

Hardware

Component Interface Role
ESP32 board USB serial, 115200 baud Receives the text to translate from the serial console and runs the whole sketch in loop().
Piezo buzzer GPIO 18 Plays every dot and dash as a fixed 1 kHz tone.
16×2 LCD + I2C backpack I2C, address 0x27 Powered from the board's 5 V pin. The backpack's on-board potentiometer has to be trimmed by hand before any text is visible.

Signal flow

The whole program is a single polling loop. Text arrives one character at a time, is matched to a pattern function that drives the buzzer, and is then mirrored to the display.

Each pass through loop():

  1. Check whether the serial console has anything waiting.
  2. Read a single character and match it, case-insensitively, against the 26 letters, the 10 digits and the space.
  3. Call the matching pattern function, which composes the right sequence of dots and dashes (a space calls the word pause instead).
  4. Echo the character back to the serial console, wait 100 ms and clear the LCD.
  5. Write whatever is still waiting in the serial buffer to the LCD.

Timing

A single base time unit (timeUnit, 100 ms) drives every symbol, so the whole transmission can be rescaled by changing one number. The durations follow the international 1:3:3:7 ratios for dot, dash, letter gap and word gap:

Element Tone Delay afterwards
Dot 1 unit (100 ms) 2 units (200 ms)
Dash 3 units (300 ms) 4 units (400 ms)
Letter pause - 3 units (300 ms), added after a letter's last element
Word pause - 7 units (700 ms), on a space

At a 100 ms unit the nominal sending speed is 12 words per minute (1200 ms divided by the unit length, the standard PARIS convention).

Character encoding

Each of the 26 letters and 10 digits has its own hand-written function that strings together dot() and dash() calls, built from the internationally established Morse table: 

A  .-      K  -.-     U  ..-     0  -----
B  -...    L  .-..    V  ...-    1  .----
C  -.-.    M  --      W  .--     2  ..---
D  -..     N  -.      X  -..-    3  ...--
E  .       O  ---     Y  -.--    4  ....-
F  ..-.    P  .--.    Z  --..    5  .....
G  --.     Q  --.-               6  -....
H  ....    R  .-.                7  --...
I  ..      S  ...                8  ---..
J  .---    T  -                  9  ----.

Display

The 16×2 LCD is addressed at 0x27 and initialized with its backlight on. After every character has been played, the display is cleared and then filled with the text read from the serial buffer, so it always shows the most recent input rather than an ever-growing log.

Challenges

Swapping in a colleague's ESP32 after the original board failed, and figuring out that the LCD's backlight needed the potentiometer on its I2C module manually trimmed with a screwdriver before any text would become visible on the display.

Limitations & next steps

Display and playback are coupled: the display update consumes everything left in the serial buffer, so for a multi-character line the first character is played as Morse and the remainder is mirrored to the LCD in one go. Queuing incoming characters, playing them one by one and echoing each as it plays would keep the two paths in step.

Pauses and character set: the digit functions (and letter O) never call the letter pause, so consecutive digits run together, and anything outside letters, digits and space, punctuation included, is silently ignored.

Structure: 36 near-identical functions could collapse into a single lookup table of patterns and one playback routine, which would shrink the sketch considerably and remove the copy-paste risk. Playback also relies on blocking delay() calls, so the board can do nothing else while a message plays.
